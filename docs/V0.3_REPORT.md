# RustMoku V0.3 完成报告

基于正式 V0.2 提交 `08232e4` 完成，工作区版本为 0.3.0。修改尚未提交。
保留 Core → Engine → Native 边界、Safe Rust、MIT OR Apache-2.0 许可，以及
Alpha-Beta、迭代加深、TT、PV。未增加第三方依赖，也未实现 V0.4 功能。

1. **V0.2 CR 修正。** generation 使用 u8 wrapping_add；相对年龄使用
   wrapping_sub，普通回绕不清空 TT。显式 clear/resize 保留。替换按同 key、
   空槽、相对年龄、深度、槽位确定；entry/bucket 仍为 16/64 字节。
   新增容量、条目数、固定最多 1024 桶的 hashfull 采样、替换计数。
   PERFORMANCE 的正式 V0.2 revision 已改正为 `08232e4`。
   Native 复测还复现了旧 TT 跨搜索深度污染：较深子局面缓存使较浅祖先搜索
   得到 19380 而冷搜索为 -580。分数/界限复用收紧为相同剩余深度；较深条目
   仍可提供合法排序落点。回归测试和界面复测均通过。

2. **BitBoard256。** engine-private `[u64; 4]`，32 字节，索引直接对应
   Move.index()；最后 31 bits 不可落子。提供 set/clear/test、OR/AND/and-not，
   使用 trailing_zeros 和清除最低位进行升序遍历。无 unsafe、HashSet 或堆分配。

3. **CandidateFrontier。** 两个 bitboard 和 `[u8;225]` 引用计数，实际 296
   字节。每次 make/unmake 更新最多 25 个计数；候选集为 frontier 去除 occupied。
   预计算 radius-two mask 含中心；空盘只生成 CENTER。终局返回空候选。

4. **LineKey 编码。** u16，偏移 `[-4,-3,-2,-1,+1,+2,+3,+4]` 从最低位开始，
   每格 2 bits；00 Empty、01 Black、10 White、11 Wall。中心不编码。
   四方向和边界由编译期几何表确定。

5. **Pattern table。** 65,536 个 key，每项 Black/White 两个字节，实际
   131,072 字节，静态表按 64 字节对齐。独立语义分类器在 Cargo build.rs
   中生成数据；运行时只有连续数组索引。另有 4,096 字节的四方向聚合表。
   普通 Release 搜索不运行分类器，也没有运行时初始化锁。

6. **ThreatProfile。** 1 字节 Copy 值，分为 Quiet、Three、OpenThree、
   DoubleThree、Four、FourThree、DoubleFour、OpenFour、WinningMove。
   一方向 Five 为直接胜点；两个 Four 为 DoubleFour；Four + OpenThree
   为 FourThree；两个 OpenThree 为 DoubleThree。方向类根据下一步成五和
   后续胜点数量定义，断三、断四采用同一套语义，不依赖连续串或 regex。
   详细优先级及受限窗口含义见 [ARCHITECTURE.md](ARCHITECTURE.md)。

7. **增量 PatternState。** 实际 3,224 字节：occupancy、225×4 个 LineKey、
   每格一个 u32 DirectionSet、225×2 个 profile、2×9 个 u16 聚合计数。
   LINE_INFLUENCES 每步最多影响 32 个不同中心，每个只更新一个方向。
   方向类不变时跳过聚合；profile 不变时跳过计数变更。occupied 中心的 line
   和方向缓存也维护，故 undo 只需 Move + Stone，PatternUndo 为 2 字节。
   SearchState<PatternEvaluator> 共 6,992 字节，包含未启用的 fallback Option
   预留空间；默认只初始化和更新一个棋型缓存。

8. **Evaluator trait。** 使用关联 State/Undo，以及 initialize、make_move、
   unmake_move、evaluate，保持泛型静态分发。PatternEvaluator 持有 PatternState；
   ClassicalEvaluator 的 State/Undo 都是 ()。可选 cached_patterns 钩子使排序
   复用 evaluator 的缓存；无该缓存的 evaluator 使用独立的增量排序缓存。
   SearchState 在 Core 成功接受落子后统一更新所有 sidecar，失败不部分修改。

9. **评估权重。** 按上面九个 profile 顺序集中定义为
   `[0,20,200,2000,10000,50000,100000,120000,1000000]`。
   评估只读取九个计数差，返回行棋方视角分数，限制在 ±10,000,000，
   与 ±100,000,000 的 mate 区间隔离。参数是未调优的第一版，不宣称最优。

10. **差分正确性。** 全部 225 radius masks 对比慢几何；65,536 个双颜色
    key 对比语义分类器并检查颜色/镜像对称；全部 6^4 个方向组合对比分支参考。
    候选集 48 组、PatternState 32 组长序列逐步 make/unmake 重算；两种 evaluator
    各 16 组 SearchState 生命周期检查。另覆盖整盘 225 步和棋及完整撤销、非法
    transition 原子性、棋盘边角、四方向、断型、复合威胁、所有空格双颜色
    would_win 对照、真实递归恢复、canonical tie、PV、TT 深度与回绕。
    86 项工作区测试和 72 项 Release 引擎测试通过。

11. **搜索热路径变化。** 候选生成不再扫 occupied 或重建 225 个布尔标记；
    排序不再执行 would_win/5×5 扫描，改为缓存威胁、预计算中心偏置和 u32
    优先级排序；默认叶点评估不再扫整盘。每节点仍保留 Core 合法转移和新胜者
    检测、边界检查、TT、固定数组排序和 PV 拷贝。只有根部构建状态及最终结果
    分配；ClassicalEvaluator 的参考扫描保留在显式选择的路径中。

12. **V0.2 / V0.3 Release 比较。** 本次重复测量的 depth=4 中位耗时：

    | Fixture | V0.2 ms | V0.3 ms |
    |---|---:|---:|
    | opening | 13.503 | 4.115 |
    | balanced_midgame | 19.034 | 7.956 |
    | tactical_attack | 12.856 | 3.932 |
    | forced_defense | 4.836 | 3.370 |
    | transposition_rich | 24.169 | 5.956 |

    depth=6 opening 从 3548.430 ms / 5,803,248 nodes 变为 324.509 ms /
    788,572 nodes。forced_defense 最新批次为 319.881 → 341.776 ms，节点增加
    45.4%，NPS 增加 36.1%；该回归和时间波动均如实保留。新评估器会改变分数
    和树形，性能不是棋力证明。作为控制，显式 ClassicalEvaluator 的 quick/deep
    共 10 个最佳落点和分数全部与 V0.2 基线一致。
    完整历史数据、深搜索、统计及方法见 [PERFORMANCE.md](PERFORMANCE.md)。

13. **微基准与 profiling。** 同一 balanced fixture 下，慢候选生成 214.89 ns，
    增量生成 48.26 ns；Classical 评估 386.69 ns，聚合评估 1.76 ns；完整
    SearchState make/unmake 为 198.09 ns/pair。WPR 指出初版聚合占 69.2%
    进程采样时间，随后排序占 33.4%。逐项优化并重测后，PatternState pair 从
    1176.45 ns 降至最终 136.67 ns。Release 汇编确认消除了额外 occupancy
    拷贝，局部更新没有除法，仍保留 Safe bounds checks。计时为观测值。

14. **TT 容量实验。** depth=8 opening，三次冷搜索中位值：

    | MiB | Nodes | Replacements | Hashfull ‰ | ms |
    |---:|---:|---:|---:|---:|
    | 64 | 4,936,928 | 70,704 | 449 | 2554.721 |
    | 256 | 4,936,914 | 630 | 114 | 2493.925 |
    | 512 | 4,936,913 | 51 | 56 | 2560.069 |
    | 1024 | 4,936,913 | 7 | 29 | 2680.330 |

    大表减少替换，但仅省 14–15 个节点；两批测量的 64/256 耗时排序还出现
    反转，尚无稳定收益支持扩大默认内存。默认保留 64 MiB，配置和 resize
    可直接测试更大容量。

15. **实际验证。** 以下全部成功执行：

    ```text
    cargo fmt --all -- --check
    cargo check --workspace --all-targets
    cargo clippy --workspace --all-targets --all-features -- -D warnings
    cargo test --workspace --all-features
    cargo test --release -p rustmoku-engine
    cargo build --release -p rustmoku-native
    cargo run --release -p rustmoku-engine --example search_bench
    ```

    另运行 deep、四容量实验、两套 Classical 控制基准、hotpath_bench、
    WPR/xperf 和 Release 汇编检查。Native 实际测试了启动、落子/AI 应答、
    occupied 拒绝、换边、新局、深度/TT/PV 展示和跨局面缓存修正。

16. **已知限制。** Pattern 是九格内的 Freestyle continuation 特征，不是完整
    必胜证明；权重未调优，重叠威胁可能重复计数。GUI 仍同步搜索，无时控/取消。
    此版没有引入 unsafe、padding Core、PVS、aspiration、LMR、quiescence、
    VCF/VCT、NNUE、Arena、多线程、服务端、Renju 或 Swap。精确深度复用保证
    固定 horizon 语义，同时可能放弃部分较深缓存的截断机会。

17. **只建议 V0.4。** 下一步以减少节点为目标，先评估 PVS、aspiration 和
    history/killer 排序；再分别论证 LMR 和 quiescence。每项配套固定局面回归、
    Release 测量和能体现棋力的对局证据。本轮未实施这些功能。
